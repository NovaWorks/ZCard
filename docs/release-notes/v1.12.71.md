# v1.12.71

## 🐛 修复:货源加价基数错误(拉到上游成本价导致卖价不对)

**反馈**:上游售价 7.5,同步后本地卖价却按 6.1(上游的上游供货价/成本价)计算,
加价没有按"上游卖价"生效。

**根因**:`SupplySyncService::computeInitialPrice` 的加价基数**优先取上游成本价
`factory_price`**(6.1),上游售价(7.5)只作兜底 —— 而 acg-faka 的
`factory_price` 是上游站自己的进货价(上游的上游对接价格),对本站而言
只是成本参考,不是卖价参照。于是本地售价 = 6.1 × 加价,而不是 7.5 × 加价。

**修复**:加价基数改为**上游售价优先**:
- `base = upstreamPrice > 0 ? upstreamPrice : factoryPrice`;
- 上游售价 7.5 + 加价 10% → 8.25(此前为 6.71);
- 上游售价缺失(0)时才回退成本价兜底。

**同时(上一轮延续)**:货源新增「自动跟随上游调价」开关(默认开启):
- 每次同步按加价规则重算本地售价,上游调价自动生效;
- 运营在后台**手动改过售价**的商品自动保护(price_manual 标记),不被同步覆盖;
- 待审(pending)定价模式不自动重算,保持人工审核。

**已验证的数值**:上游售价 800 分 / 成本 500 分 / 加价 10% → 本地售价 880 分
(修复前为 550 分)。
