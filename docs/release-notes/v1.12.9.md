# v1.12.9

## 🔒 登录态安全修复:后台登录 7 天过期 + 登录超时提示

### 背景(客户反馈)
客户关闭网页后隔一段时间再打开后台,**上次的登录态仍然有效**——因为 Sanctum token 永不过期
(`config/sanctum.php` 的 `expiration = null`),且 sysadmin 把 token 持久化在 localStorage。

### 修复
- **`config/sanctum.php`**:token 有效期从「永不过期」改为 **7 天**
  (`expiration = env('SANCTUM_TOKEN_EXPIRATION', 60*24*7)`),到期后 API 自动返回 401,
  可通过 `.env` 的 `SANCTUM_TOKEN_EXPIRATION`(分钟)按需调整。
- **sysadmin**:401 提示文案改为「**登录超时,请重新登录**」(中英文),配合已有的 401 自动登出
  逻辑,过期后弹提示并跳转登录页(带 redirect 回跳)。

### 前端登录态修复(storefront,老客户"已登录却提示先登录")
- **`stores/auth.ts`**:`fetchUser()` 原先**任何错误(网络抖动/服务器 5xx/超时)都清除 token**,
  导致老客户被静默登出后点击充值/验证码入口被路由守卫拦回登录页。现改为**仅 401 时清 token**,
  瞬时故障保留登录态。
- **`api/request.ts`**:401 统一处理——清 token + 跳转登录页并携带 `redirect` 回跳参数。
- **`views/Login.vue`**:登录成功后跳回 `redirect` 指向的原页面(而非固定回首页)。

### 验证
- 有效 token → `/auth/me` 200;过期 token(expires_at 设为过去)→ 401。
- Guard 按 `created_at + 7天` 判断(token 永不过期配置已移除),存量 token 7 天后同样失效。
- sysadmin 端到端:登录后台 → 模拟 token 过期 → 刷新 → 自动跳转 `#/auth/login?redirect=/`,
  提示「登录超时,请重新登录」。
- storefront:有效 token 正常访问充值页;失效 token 自动跳登录带 redirect,登录后回跳原页面。
- `storefront` typecheck 通过、`sysadmin` typecheck+build 通过,产物已提交。
