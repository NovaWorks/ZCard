# v1.12.69

## 🐛 修复:在线更新时 Composer 删除旧 vendor 文件失败导致中断

**反馈**:在线更新执行依赖安装时,Composer 尝试删除旧的 vendor 文件失败,
导致整个安装过程回滚/中断;怀疑"每次请求都会删除"。

**排查结论**:
- **不是每次请求删除**。Composer 仅在点击「在线更新/回退」时执行(带原子锁防并发),
  日常页面请求完全不碰 composer。
- **真实根因**:Composer 在依赖增删时会删除/替换旧包文件。若服务器**曾用 root
  执行过 composer install / git pull**(面板/手动操作常见),vendor 内文件属主为
  root,而 PHP-FPM 进程以 www 用户运行 → **www 无权限删除 root 文件** →
  Composer 报 "failed to remove" 并中断整个安装。

**修复**:
1. **composer 执行前预检 vendor 可写性**:不可写时直接给出明确修复指令
   (`chown -R www:www 站点目录`),不再让 Composer 中途炸掉;
2. **失败诊断增强**:Composer 输出含删除失败特征( failed to remove /
   Permission denied 等)时,自动识别为 vendor 属主问题并提示对应 chown 命令;
3. **安装向导/命令行安装的权限修复**同步覆盖 vendor 目录(此前只修
   storage/bootstrap-cache)。
