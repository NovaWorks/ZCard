# v1.12.91

## 🛠 客服脚本仍不加载（Crisp/Chatwoot）：CSP 白名单放行口径修复

**客户反馈**：填写了 Chatwoot/Crisp 官方代码，且把 `client.crisp.chat`、`settings.crisp.chat` 都加进了受信域名白名单，前台依旧不显示客服。

**根因（两个叠加问题）**：

1. **CSP 只放行"粘贴代码里出现过的域名"**：白名单里写了 `settings.crisp.chat`，但安装代码文本里没有它，CSP 的 `script-src` 不会包含该域名 → Crisp 主脚本加载后，SDK 运行期去 `settings.crisp.chat` 拉取网站设置被 CSP 拦截，组件初始化失败。
2. **WebSocket 通道域名遗漏**：v1.12.90 把 `connect-src` 的 `wss:` 通配收紧为按主机放行，但 **Crisp 的实时通道在独立子域名 `client.relay.crisp.chat`**（Chatwoot 才是与 SDK 同域），不在放行列表 → 消息通道连接失败。

**修复内容**：

- `ServiceWidgetScript::allowedOrigins()`：CSP 改为**直接放行白名单内的全部域名**（不再只认代码文本中出现的域名），涵盖第三方 SDK 的运行期子域名依赖；
- 白名单最终生效口径 = **默认官方域名 + 用户追加域名**（默认域名包含 Crisp 全套：`client/settings/client.relay/image/storage.crisp.chat` 与 Chatwoot 全套：`app/cdn.chatwoot.com`），用户只需追加自建域名；
- 默认域名补入 `client.relay.crisp.chat`、`image.crisp.chat`、`storage.crisp.chat`，`wss://client.relay.crisp.chat` 进入 `connect-src`；
- 后台设置页提示文案同步更新（说明"最终生效 = 默认官方域名 + 追加域名"）；
- 回归测试更新/新增 4 个：白名单域名即使不在代码文本中也进 CSP、默认官方子域名始终放行、未知域名仍被排除、Crisp relay 的 wss 源出现在 CSP 中。

## 升级与使用

- 通过后台「在线更新」或 `git pull && composer install --no-dev` 升级；无数据库变更。
- 无需改动任何配置：留空白名单或维持现有填写均可；保存设置后**强制刷新（Ctrl/Cmd+Shift+R）前台页面**验证客服气泡。
- 使用自建 Chatwoot/Crisp 的站点：在受信域名白名单追加自建域名即可（如 `chat.example.com`）。
