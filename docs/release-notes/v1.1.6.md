# v1.1.6

## 🐛 修复:版本号显示 v1.0.0 + 在线更新 shell_exec 报错

### 问题 1:版本号永远显示 v1.0.0

**现象**:用最新代码安装,但后台/在线更新页显示版本 `v1.0.0`,而非实际的 `v1.1.x`。

**根因**:`AppHelper::versionFromGit()` 用 `git describe --tags` 读版本号,但 Symfony Process 底层依赖 `proc_open`。宝塔默认禁用 `proc_open` → git 命令执行失败 → 回退到 `config/app.php` 的兜底值 `1.0.0`。

**修复**:新增**纯文件读取方案**作为兜底 —— 直接读 `.git/refs/tags/` 目录下的 tag 文件,按语义版本排序取最大值。这是纯文件操作,**不执行任何命令,不受 `disable_functions` 限制**。

```
版本号读取优先级:
1. git describe --tags    (需 proc_open;宝塔/容器常禁用)
2. 读 .git/refs/tags/      (纯文件操作,新增;兜底)  ← 本次新增
3. config/app.php version  (最后防线,已更新为 1.1.6)
```

### 问题 2:在线更新报 `Call to undefined function shell_exec()`

**现象**:点「检查更新」或「执行更新」,报 `更新失败: Call to undefined function App\Http\Controllers\Api\Admin\shell_exec()`。

**根因**:`UpdateController::shell()` 直接用 `shell_exec()` 执行 git/composer 命令。宝塔把 `shell_exec` 加入 `disable_functions` → PHP fatal error,更新流程直接中断。

**修复**:
- `shell()` 方法改用 **Symfony Process**(统一封装,设置 600s 超时),替代裸 `shell_exec`
- 执行前检测 `proc_open` 是否可用,被禁用时抛**清晰可读的异常**(提示去宝塔放行 `proc_open` / `shell_exec`),而非 PHP fatal error
- `buildFrontend()` 里的 `shell_exec` 也统一替换,构建失败时优雅跳过(使用仓库已有编译产物)

### ⚠️ 在线更新仍需放行函数

在线更新功能(git pull + composer install)本质上需要执行系统命令,因此**必须**在宝塔面板放行以下函数:

**宝塔面板 → PHP-8.4 → 设置 → 禁用函数**,移除:
- `proc_open`(必须)
- `shell_exec`(必须)
- `exec`(推荐)

不放行的话,在线更新功能无法使用(但系统其它功能不受影响)。
