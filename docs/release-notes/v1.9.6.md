# v1.9.6

## 🔧 本次更新内容

### 1. acg-faka 货源对接全链路修复

基于 acg-faka 源码重新通读对接流程，修复 4 个协议 bug：

| # | 问题 | 修复 |
|---|---|---|
| 1 | 查单路径 `/shared/commodity/query/{no}` 恒 404 | 改为 `POST /shared/commodity/query` + body 携带 `tradeNo`（acg-faka Kernel 按 `/` 拆段，路径参数会被拼进类名导致 404） |
| 2 | `upstream_order_id` 存的是我方单号，重试永远查不到 | 改为存上游返回的 `tradeNo`（其查单按 `trade_no` 字段匹配） |
| 3 | 购买 N 张卡只生成 1 条发货记录 | 多张卡密按 `PHP_EOL` 拆分后逐条写入 |
| 4 | 上游成本恒为 0，无法对账 | `amount`/`tradeNo` 元→分换算入库 |

**前端错误透传**：`sysadmin/src/utils/http/error.ts` 原先只要有 HTTP 状态码就丢弃后端错误体，导致所有上游诊断信息（伪静态未配 / WAF 拦截 / 密钥错误）被替换成「服务器内部错误」。已修复，诊断信息可正确展示。

**新增调试端点**：`GET /api/admin/supply-sources/{id}/products/debug` 返回上游原始响应（HTTP 状态码 + 响应体 + 提示），快速定位「测试连通成功但拉不到商品」的问题。

### 2. 上游驱动签名字节一致性修复

`ZCardDriver` / `DujiaoNextDriver` 对请求 body 做了**双重 md5**，与 `spec §4.2` 的 `md5(rawBody)` 及服务端 `SupplyAuth` 口径不符，导致 `driver=zcard` 的货源**恒定 401**。已修复：

- `signedHeaders()` 第三参改为 body 原文，md5 只在函数内做一次
- 新增 `encodeBody()` / `postRaw()`，保证「签名字节 == 发送字节」
- 删除 `postJson()` 便捷版，杜绝再次配错

### 3. 货源 404 自诊断

调用 `supply-sources/{id}/products/*` 时若 id 不存在，不再返回无从查起的裸 404，改为返回自诊断 JSON：

```json
{"ok": false, "error": "货源不存在: id=3。可用货源 id: 6, 9, 10。请先 GET /api/admin/supply-sources 获取真实 id。"}
```

### 4. 测试回归修复

默认货币种子迁移（`2026_08_03_000010_seed_default_currencies`）预置 CNY/USD/EUR 后，多个测试按空表假设 `Currency::create('CNY')` 撞唯一索引失败。已全部改为 `firstOrCreate` / `updateOrCreate`，**全量测试 129 通过**。
