# v1.1.5

## 🔧 安装体验强化:自动修复目录权限 + 部署排错文档完善

### 背景

v1.1.2~v1.1.4 修复了"未安装跳转安装向导",但实际部署中暴露出更深层的**权限问题**:`composer install` / `git pull` 用 root 执行后,`storage/`、`bootstrap/cache/` 目录属主是 root,而宝塔 PHP-FPM 以 www 用户运行 → 不可写 → 500。这是最常见的"装完就 500"根因,且非常隐蔽(CLI 命令以 root 跑都正常,只有 Web 请求才崩)。

### 新增:安装流程自动修复目录权限

- **Web 安装向导**(`InstallController::run`):安装执行前自动 `fixPermissions()`,递归创建并 `chmod 775` 关键目录(storage 全部子目录 + bootstrap/cache)
- **CLI 安装命令**(`zcard:install`):同样自动 `fixPermissions()`,且以 root 运行时**额外自动 chown** 修正属主为 PHP-FPM 用户(自动探测 www / www-data / nginx / apache)

涉及的目录:`storage/`、`storage/app/`、`storage/app/public/`、`storage/framework/{cache,cache/data,sessions,views}/`、`storage/logs/`、`bootstrap/cache/`

> ⚠️ Web 安装向导受 PHP-FPM 进程权限限制,只能 chmod 不能 chown。如果用 root 跑过 composer/git,Web 向导的 chmod 可能不够,仍需手动 `chown -R www:www storage bootstrap/cache`。CLI 的 `zcard:install` 以 root 运行时可自动 chown,推荐优先用 CLI 安装。

### 新增:部署排错文档(问题 5/6/7)

[`docs/部署安装指南.md`](../部署安装指南.md) 新增三个高频问题章节:

- **问题 5:访问首页 500 / 白屏(storage 目录不可写)** — 最常见根因,`chown -R www:www storage bootstrap/cache` 解决
- **问题 6:`tempnam(): file created in the system's temporary directory`** — 宝塔 `open_basedir` 限制,放宽到项目父目录 + /tmp
- **问题 7:`Module "mbstring" is already loaded`** — php.ini 重复加载扩展,删除多余 extension 行

错误速查表同步更新,新增 5 条部署后高频报错的根因速查。

## ⬆️ 升级

```bash
git pull origin main
composer install --no-dev --optimize-autoloader
chown -R www:www storage bootstrap/cache vendor   # 权限修复
rm -f bootstrap/cache/*.php
php artisan optimize:clear
/etc/init.d/php-fpm-84 restart
```

本次为安装流程强化 + 文档,无数据库变更,无前端变更。
