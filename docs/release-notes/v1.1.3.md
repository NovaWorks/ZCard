# v1.1.3

## 🐛 关键修复:安装向导页面 JS/CSS 加载失败 + clone 后无 .env

### 问题 1:install 页面白屏,静态资源 404

v1.1.2 修复了"未安装跳转安装向导",但安装向导页面打开后**白屏** —— 控制台报 `/assets/index-xxx.js` 等 JS/CSS 文件 404。

**根因**:`storefront/vite.config.ts` 缺少 `base` 配置。Vite 默认 `base='/'`,导致编译出的 `index.html` 引用 `/assets/index-xxx.js`;但物理产物输出在 `public/storefront/assets/` 下 —— URL 路径与物理路径**差了一层 `storefront`**,Nginx 在 `public/assets/` 找不到文件 → 404。

**对比佐证**:后台 sysadmin 的配置是 `base=/admin/` + `outDir=public/admin/`,路径自洽所以正常;storefront 这边配置不对称。

**修复**:`storefront/vite.config.ts` 生产构建设置 `base: '/storefront/'`(与 sysadmin 的 `.env.production` 模式一致),重新编译。修复后 `index.html` 引用 `/storefront/assets/xxx.js`,直接命中物理文件。

### 问题 2:clone 后没有 .env 导致 500

`git clone` 后,由于 `.env` 被忽略,服务器上不存在该文件,Laravel 回退用默认值(`DB_CONNECTION=sqlite`)→ 找不到 sqlite 文件 → 所有请求 500,连安装向导都无法启动。

**修复**:
- 从 `.gitignore` 移除 `.env` 的忽略规则
- 提交一份**安全默认值**的 `.env`(`APP_KEY`、`CARD_ENCRYPTION_KEY`、数据库凭据均留空,无任何真实密钥)
- clone + `composer install` 后即可直接访问,自动跳转 `/install` 安装向导填充真实配置

> 已有的 `.env.backup` / `.env.production` / `.env.local` 仍被忽略,含真实凭据的文件不会进仓库。

### 附带:phpunit.xml 补充测试密钥

因 `.env` 改为安全默认值(`APP_KEY` 空),phpunit.xml 补充了测试专用的 `APP_KEY` 与 `CARD_ENCRYPTION_KEY`,让测试不依赖 `.env` 文件。

## ⬆️ 升级

```bash
git pull origin main
composer install --no-dev --optimize-autoloader
rm -f bootstrap/cache/*.php
php artisan optimize:clear
```

> ⚠️ **如果你之前已手动创建了 `.env`**:`git pull` 时你的本地 `.env` 不会被覆盖(git 会保留本地修改)。但如果你是全新 clone,现在仓库自带的 `.env` 让你开箱即用。

本次为前端配置 + 配置文件修复,无数据库变更。
