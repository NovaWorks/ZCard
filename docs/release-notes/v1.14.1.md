# v1.14.1

## 🐛 修复：统计代码静默失效（issue #39）

**现象**：后台「店铺设置 → 统计代码」可以填写并保存百度统计 / GA4 代码，保存成功、无报错，
但前台不加载任何统计脚本，`GET /api/settings/storefront` 里没有统计字段，Network 中也没有采集请求。
管理员重新进入设置还能看到自己填的内容，因此很容易误以为功能正常。

**根因**：v1.12.55 的安全修复同时做了两件事——把 `footer_analytics` 移出公开配置白名单、
删除前台 `injectAnalytics()` 注入逻辑；但**后台字段、文案与持久化都被保留**，形成静默功能回归。
v1.12.90 引入的严格 CSP（`script-src 'self'` + 客服白名单）随后形成第二层阻断：
即便恢复旧注入逻辑，GA4 的 `googletagmanager.com` 脚本与 `google-analytics.com` 采集请求仍会被拦截。

**修复思路**：不恢复"任意脚本原样注入"，而是复用客服组件已审计的那套机制
（受信域名白名单 → 编译成同源 JS → CSP 精确放行）。为此把编译器抽成基类，两处共用：

- 新增 `app/Support/ThirdPartyScript.php`：从 `ServiceWidgetScript` 原样抽出的编译与 CSP 来源提取逻辑。
- `app/Support/ServiceWidgetScript.php` 瘦身为「白名单 + 标签」，**行为零变化**（既有 21 个测试全绿）。
- 新增 `app/Support/AnalyticsScript.php`：默认放行 GA4（`googletagmanager.com`、`google-analytics.com`、
  `analytics.google.com`）、百度统计（`hm.baidu.com`）、Clarity（`clarity.ms`）。

配套改动：

1. `StorefrontConfig` 新增结构化配置 `analytics{enabled, script}` 与 `analytics_allowed_hosts`；
   `public()` 只下发 `enabled` 与 `script_configured`，**原始脚本一律不进公开配置**。
2. 新增同源端点 `GET /api/settings/analytics-script`（无扩展名，规避 nginx 把 `.js` 当静态文件处理）。
3. `SecurityHeaders`：**仅当统计已启用且脚本非空**时，按白名单精确追加 `script-src` / `connect-src`；
   未启用时 CSP 一个字符都不放宽。
4. `Admin/SettingController`：脚本因引用非白名单域名被整段丢弃时返回 `analytics_script_dropped`，
   后台弹出 10 秒警告——不再"保存成功却静默失效"。
5. 前台新增 `SiteAnalytics.vue`：从同源端点加载脚本，并在 SPA 路由切换时补发
   `gtag('event','page_view')` / `_hmt.push(['_trackPageview'])`（单页应用不补发只能统计到首页）。
6. 后台设置页把失效的「统计代码」文本框换成 **启用开关 + 统计代码 + 受信域名** 三项，中英文案齐全。
7. 新增迁移 `2026_08_18_120000_migrate_footer_analytics_to_analytics_setting`：把存量 `footer_analytics`
   搬入 `analytics.script`，但**保持关闭状态**——旧脚本引用的域名未必在白名单内，
   不能在升级瞬间自动放宽 CSP 并执行远程代码。

## 🐛 修复：注册 / 登录验证码第 5 位被裁，导致反复提示「验证码错误」

**现象**：验证码图片显示不全，只能看到 4 位数字，照着输入必然报错。

**根因**：`mews/captcha` 的 `configure()` 在 `config/captcha.php` 缺少对应场景段时**什么都不做**，
直接沿用类默认值 `length = 5`、`width = 120`。字符横向位置按
`marginLeft = padding + key × (width − padding) / length` 分布，5 个字符时最后一位起点在 x≈97，
加上随机字号（26–36px）会被画出 120px 画布边界。

而 `config/captcha.php` 只有 `default / trade / flat / mini / inverse / math` 六段，
**缺少前台实际在用的 `register` 与 `login`**：

| 场景 | 使用页面 | 修复前 |
|---|---|---|
| `register` | 注册页、找回密码页 | 5 位，末位被裁 |
| `login` | 前台登录页、sysadmin 后台登录 | 5 位，末位被裁 |
| `trade` | 收银台下单 | 4 位，正常 |

`trade` 段的注释里已记录过同一个坑（"此前缺失导致 mews 用类默认值生成"），当时只补了 `trade`。

**修复**：补齐 `register` 与 `login` 两段，参数与 `trade` 完全一致（`length=4`、无背景纹理、白底、四色字）。
纯新增配置，未改动任何既有行；校验逻辑无需变动（生成与校验两侧的 `encrypt` 本就自洽）。

## 测试

- 新增 `tests/Feature/AnalyticsScriptTest.php`（7 例）：对照 issue #39 的验收标准逐条覆盖——
  GA4 只加载一次 gtag.js、公开配置不含原始脚本、未启用时 CSP 不放宽、非白名单域名整段丢弃并告警、
  百度统计可用、旧数据迁移后保持关闭。
- 新增 `tests/Feature/CaptchaSceneConfigTest.php`（4 例）：场景配置段必须存在、每字符可用宽度 ≥28px、
  实际生成位数与配置一致、图片尺寸与配置一致。**移除修复后 4 例全红**，报错为「场景 register: 实际生成 5 位」。
- 全量 `php artisan test`：**427 passed**；`pnpm typecheck`、`./vendor/bin/pint` 通过。

## 升级与使用

- **本次含 `config/` 改动**：生产若执行过 `php artisan config:cache`，升级后必须
  `php artisan config:clear && php artisan config:cache` 才会生效（走后台「在线更新」会自动执行）。
- 含一条数据库迁移（仅搬运设置数据，不改表结构）。
- 前台与后台产物已随本次发布提交，无需在服务器上构建。
- 升级后如需启用统计：进入后台「店铺设置 → 页脚」，确认统计代码内容后打开「启用统计」开关；
  若代码引用了 GA4 / 百度统计以外的域名，需一并填入「统计受信域名」，否则保存时会提示脚本已被丢弃。
