# v1.14.0

## 🐛 修复：顾客付款后「查不到订单 / 看不到卡密」（游客查单凭证链断裂）

**现象**：顾客在前台下单付款后，去「订单查询」页用**邮箱 / 手机号**查单，页面始终显示未找到；
即便管理员在后台确认订单已支付、卡密已发货（含人工补发），顾客侧仍然看不到任何卡密。

**根因**：v1.12.61 / v1.12.90 的安全整改把「读取卡密」收紧为三选一授权
（登录本人 / 订单访问凭证 `access_token` / 查询密码，见 `OrderService::canAccessOrder`），
但前端保存与传递凭证的方式没有跟上这次收紧：

1. **凭证存在 `sessionStorage`** —— 标签页一关即失效。顾客付款后关掉页面、次日再来查单，凭证已不存在。
2. **凭证以订单号为键** —— 而查单页引导的是「输入订单号 / 邮箱 / 手机号」。顾客按**联系方式**查单时，
   前端根本取不到凭证（无法预知该联系方式命中哪几笔订单），请求不带任何凭证 →
   服务端逐笔授权失败 → 返回空列表。**这条路径是必现的，与是否已发货无关。**
3. 「查询密码」在下单表单里是**可选项**，未填写的游客订单因此失去了最后一条找回途径。

### 修复

**服务端**

- `app/Support/OrderService.php`：`canAccessOrder()` / `searchOrders()` 接受**一批**访问凭证
  （`string|array`），逐笔比对；新增 `MAX_ACCESS_TOKENS = 20` 上限，避免被当作哈希计算放大器。
  授权口径本身未放宽——凭证不匹配的订单依旧读不到。
- `app/Http/Controllers/Api/OrderController.php`：
  - `POST /api/orders/query` 新增 `access_tokens[]` 参数（每项 64 位，最多 20 个），
    与原有的单个 `access_token` 并存，旧客户端不受影响。
  - `POST /api/orders`、`POST /api/orders/batch`：**开启「查询密码」时，游客下单必须设置查询密码**
    （≥6 位）。登录用户凭账号即可在「我的订单」读取卡密，不受此约束。

**前台（storefront）**

- `utils/orderAccess.ts`：凭证改存 `localStorage`（关闭标签页不再丢失）；新增
  「联系方式 → 订单号」索引与 `accessTokensForKeyword()`；读到旧 `sessionStorage` 凭证时
  自动迁移，老用户不断链；关键字未命中索引时回退提交本机全部凭证（≤20 个），
  兜住「换个邮箱查」这类错配。
- `OrderQuery.vue` / `PayResult.vue` / `Pay.vue`：查单一律改用 `accessTokensForKeyword()`，
  **按邮箱 / 手机号查单现在会正确携带凭证**。
- `Checkout.vue`：下单时按联系方式建立凭证索引；游客必填查询密码，并提示
  「换设备或清除浏览器数据后，需凭联系方式 + 查询密码取回卡密」。

## ⚠️ 破坏性变更

- **开启「查询密码」（默认开启）时，游客下单必须填写查询密码**，否则 `POST /api/orders`
  与 `/api/orders/batch` 返回 422。自建前端或直连下单 API 的集成方需要同步补上 `password` 字段。
  不需要该约束的站点，可在后台关闭「启用查询密码」——但那样游客订单将再次只能依赖本机凭证，
  换设备即无法找回。
- 本次修复**对既有订单无效**：老订单的凭证已随 `sessionStorage` 消失，顾客只能凭查询密码或
  登录账号读取。历史订单如需补救，请在后台订单详情中查看卡密后直接发给顾客。
