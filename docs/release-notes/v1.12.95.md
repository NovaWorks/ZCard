# v1.12.95

## 🐛 修复：被安全校验拒绝的在线回滚会泄漏操作锁（issue #22）

**报告**：[#22](https://github.com/NovaWorks/ZCard/issues/22) 指出
`UpdateController::rollback()` 在持有 `zcard:system-update` 原子锁（600 秒 TTL）之后才执行
安全预检（降级基线 + 回滚次数上限），而这两个 422 拒绝分支位于主流程 `try/finally` **之前**，
直接 `return` 时不会调用 `release()`；预检中的异常（如 git 命令执行失败）同样泄漏。

**核实**：属实。`rollback()` 的执行顺序为

```
拿锁(acquireOperationLock) → 预检①降级基线(422 直接返回) → 预检②回滚次数上限(422 直接返回)
→ 计数+1 → 写 update.lock/update.log → try { 主流程 } finally { release() }
```

① ② 以及预检阶段 `shell()` 抛异常，都绕过了 `finally`。一次本应无副作用的 422 安全拒绝
会把操作锁占用到 600 秒 TTL 过期，期间所有「在线更新 / 回退」请求持续返回
**409「已有更新或回退正在进行中」**，最长约 10 分钟（生产 `file`/`redis` 缓存驱动下可复现；
`array` 测试驱动在对象销毁时自动释放进程内锁，因此此前测试未能发现）。

> 对比：`update()` 拿锁后立即进入 `try/finally`，没有此问题。

**修复内容**（`app/Http/Controllers/Api/Admin/UpdateController.php`）：

- 把降级基线与回滚次数上限两项预检包进**独立的 `try/catch`**：
  - 任一 422 拒绝分支返回前先 `$operationLock->release()`；
  - 预检异常（如 git 命令执行失败）在 `catch` 中释放锁后原样抛出；
  - 预检全部通过才保留锁进入主流程（主流程 `finally` 照旧释放）。
- 顺带收口最后一个理论泄漏窗口：`update.lock` / `update.log` 的文件写入移入主 `try`，
  即使写入抛异常，`finally` 也会释放操作锁。
- 每条路径只释放一次锁（拒绝/异常路径不进主流程，成功路径只在 `finally` 释放）。

**回归测试**（`tests/Feature/UpdateRollbackLockReleaseTest.php`）：

- 用 **`file` 缓存锁驱动**复现生产行为（`array` 驱动无法复现）；
- 置 `storage/app/rollback.count = 3` → 管理员密码复验后请求回滚 → 断言返回 422；
- **关键断言**：422 拒绝后立即可重新获取同名锁。修复前该断言失败（锁被占用）；
  修复后通过。已按红→绿流程验证（旧代码上红、新代码上绿）。

**影响范围**：仅在线回滚的安全预检路径；主流程、`update()`、版本检查均未改动，无数据库变更。

## 升级与使用

- 通过后台「在线更新」或 `git pull && composer install --no-dev` 升级；**无数据库变更**。
- 若生产环境此前已出现「回滚被 422 拒绝后更新/回退持续 409」的现象：锁会在最多 10 分钟后
  自动过期恢复；升级本版本后此类拒绝将不再占用锁。
