# v1.2.0

## 🔧 在线更新:.env 冲突自动处理(参考 acg-faka 思路)

### 问题

`git pull` 更新时报 `Your local changes to .env would be overwritten`,在线更新无法完成。根因:旧版本 `.env` 曾被 git 跟踪,用户修改后与仓库版本冲突。

### 修复:更新流程自动保护用户文件

参考 acg-faka "更新永远不碰用户配置"的思路,在 `UpdateController` 的 git pull/reset 前后加入文件保护:

1. **`preserveUserFiles()`**(git pull 前):
   - 备份 `.env` / `.env.local` 到 `storage/app/`
   - 若文件仍被 git 跟踪(旧版本),临时 `git checkout` 让工作区干净,使 pull 不报冲突
   - 若文件已从 git 移除(v1.1.9+),无需 checkout(本来就不会冲突)

2. **`restoreUserFiles()`**(git pull 后):
   - 从备份恢复用户的真实 `.env`,**确保用户配置绝不丢失**

3. **回滚(rollback)同样保护**:`git reset --hard` 前后也走 preserve/restore

### 行为

| 场景 | v1.1.9 | v1.2.0 |
|---|---|---|
| .env 被 git 跟踪 + 本地改过 | ❌ git pull 报冲突 | ✅ 自动备份→checkout→pull→恢复 |
| .env 不在 git(v1.1.9+) | ✅ 正常 | ✅ 正常(跳过 checkout) |
| git reset --hard 回滚 | ❌ 覆盖 .env | ✅ 保护并恢复 .env |

### 参考 acg-faka 的启示

研究了 acg-faka 发卡系统的部署架构,它的核心思路:
- **不用 git pull,用 ZIP 增量包更新**(物理上不可能碰到用户配置)
- **配置用 PHP 数组 + merge 写**(`array_replace` 只改指定 key)
- **版本号写在 config 里**(单一配置源)

ZCard 作为 Laravel 项目无法完全照搬,但本次修复借鉴了"更新绝不碰用户配置"的核心原则。未来可考虑迁移到 ZIP 增量更新方案。

## ⬆️ 升级

> ⚠️ 本次升级必须用命令行(在线更新的修复就在本次更新里)。

```bash
cd <你的项目目录>

# 备份 .env(以防万一)
cp .env .env.safe

# 解决 git 冲突(临时 stash 本地改动)
git stash
git pull origin main

# 恢复 .env
cp .env.safe .env

# 权限 + 缓存
chown -R www:www storage bootstrap/cache vendor
rm -f bootstrap/cache/*.php
php artisan optimize:clear
/etc/init.d/php-fpm-84 restart
```

更新到 v1.2.0 后,以后在线更新会自动处理 `.env` 冲突,不再报错。

无数据库变更,无前端变更。
