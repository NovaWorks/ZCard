# v1.12.11

## 🐛 修复:收银台小计与应付总额货币不一致 + 验证码排障工具

### 1. 收银台小计与应付总额金额不一致(切换 USD 后)

**根因**:`Checkout.vue` 中「小计」误用了**基础货币分**(`subtotal` = `Σ price × qty`,CNY),
而「应付总额」用**展示货币分**(`totalDisplay` = `Σ price_display × qty`)。切换 USD 后
小计显示 `$6.50`(实为 ¥6.50 数值被当 USD 格式化),应付总额显示 `$0.91`,两者不一致。

**修复**:新增 `subtotalDisplay`(展示货币小计,与商品行单价/应付总额同口径),
小计改用 `subtotalDisplay` 渲染。

**验证**:USD + qty=1 → 小计/应付/提交按钮均 `$0.91`;qty=2 → 均 `$1.82`。

### 2. 验证码排障工具(DEBUG_CAPTCHA,默认关闭)

**背景**:老客户反馈「验证码输入正确仍提示错误」,本地机制验证正常(用返回答案提交成功),
疑为线上环境差异(PHP 8.4 / config 缓存 / cache 驱动)。为精确定位,临时加入调试开关:

- **`GET /api/captcha/trade`**:当 `DEBUG_CAPTCHA=true` 时,随 `src` 返回明文答案 `debug_answer`。
- **`GET /api/captcha/debug-read`**:当 `DEBUG_CAPTCHA=true` 时,读取当前 session 中验证码答案。
- 默认关闭(未设置 `DEBUG_CAPTCHA` 时 404/不返回答案),**定位完成后必须删除**。

**线上排查步骤**:
1. 在 `.env` 设置 `DEBUG_CAPTCHA=true`(确认不带引号)。
2. 访问 `https://站点/api/captcha/trade?1` → 响应含 `debug_answer`(真实答案)。
3. 用该答案在收银台提交 → 若成功,则验证码机制正常,问题在用户输入/图片可读性;
   若失败,则问题在 session/cache 一致性,需查 CACHE_STORE/Redis。
4. 排查完删除 `DEBUG_CAPTCHA` 并关闭。
