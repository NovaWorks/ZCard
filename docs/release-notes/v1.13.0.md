# v1.13.0

## 🐛 修复：金额迁移兼容 SQLite,测试环境固定为内存库开箱即用（issue #15，PR #16）

**报告**：[#15](https://github.com/NovaWorks/ZCard/issues/15) 指出两条金额单位迁移
（`2026_08_02_230000_change_card_draft_fields_to_cents.php`、
`2026_08_02_231000_change_user_group_thresholds_to_cents.php`）使用 MySQL 专用的
`ALTER TABLE ... MODIFY` 裸 SQL，SQLite 在迁移阶段即报 `near "MODIFY": syntax error`；
另外 `phpunit.xml` 只设 `DB_DATABASE=testing` 未固定 `DB_CONNECTION`，测试连什么库
取决于各自 `.env`。报告者实测 v1.12.93 上 385 个测试 335 个 error。

**核实**：属实。本机 main 复现：`DB_CONNECTION=sqlite DB_DATABASE=:memory: php artisan test`
在第一条 `MODIFY` 处失败。维护者本机另有连带症状——`.env` 的 `DB_HOST=mysql` 是 Docker
主机名，裸 `php artisan test` 曾大面积失败（361/411），与迁移问题叠加掩盖了真实回归。

**修复**（复用报告者的 PR #16，`sanrokamlan-prog` 贡献，实测通过后合并）：

1. 两条迁移的列类型变更改用 Laravel Blueprint `change()`（`bigInteger`/`decimal` +
   `default` + `comment`），由框架按驱动生成方言 SQL，MySQL 语义不变（NOT NULL、
   默认值、注释均保留）；
2. 回滚换算 `draft_premium / 100` → `/ 100.0` 等 4 处，避免 SQLite 整数除法截断
   分以下小数；
3. 新增 `tests/Feature/MigrationPortabilityTest.php`：断言 cards 与 user_groups 的
   四个金额列迁移后均为整数类型，防止再引入驱动不可移植的 DDL；
4. `phpunit.xml` 固定 `DB_CONNECTION=sqlite` + `DB_DATABASE=:memory:`——测试不再
   依赖任何外部数据库与 `.env`，裸 `php artisan test` 在任何机器开箱即用。

**验证**：

- SQLite 内存库全量 `php artisan test`：**412 passed / 1324 assertions**（报告者验证时
  为 386，main 期间新增了测试）；
- 裸 `php artisan test`（不带任何环境变量、`.env` 指向不可达 MySQL）同样 412 通过；
- `./vendor/bin/pint --test` 三个变更文件全部通过。

**影响范围**：仅测试基建与两条迁移的可移植性写法；生产 MySQL 上两列的最终类型、
默认值、注释与原裸 SQL 完全一致，已迁移过的站点无感知。无业务代码变更。

## 升级与使用

- 通过后台「在线更新」或 `git pull` 升级；无数据库变更、无依赖变更；
- 开发者此后直接 `php artisan test` 即可（或 `composer test`），无需准备 `testing`
  数据库；CI 同理。
