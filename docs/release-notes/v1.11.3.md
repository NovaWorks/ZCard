# v1.11.3

## 🔧 修复:最低 PHP 版本声明与实际依赖不一致

**背景**:composer.json 声明 `php: ^8.3`,但锁定的 Symfony 8.1.x 系列实际要求 PHP `>=8.4.1`,
导致在 PHP 8.3 环境执行 `composer install` 会因依赖冲突而失败 —— 声明的最低版本名不副实。

**修复**:
1. **Symfony 组件锁定到 7.4 系列**(console/routing/http-foundation/http-kernel/string/clock/finder/mailer/mime/process/translation/uid/var-dumper 等 17 个),Symfony 7.4 仅要求 PHP 8.2
2. **composer.json 增加 `config.platform.php: 8.3.0`**,强制 composer 按 PHP 8.3 平台解析依赖,
   保证未来 `composer update` 不会再次把 Symfony 拉回 8.x(否则会破坏 PHP 8.3 兼容)
3. `composer.lock` 已在 PHP 8.3 平台下重新解析

**效果**:最低 PHP 版本**真正降到 8.3**(Laravel 13 自身要求 `^8.3`,Symfony 7.4 要求 8.2,
两者取交集为 8.3),与 composer.json 声明一致。README / 部署指南中原有的"8.3 或 8.4"表述继续有效。

**验证**:
- PHP 8.3.33 镜像 + composer install:依赖解析通过,无冲突
- 全部 Symfony 包检查:无任何包要求 PHP 8.4+(polyfill 类包本身支持 7.2+)
- 本机(PHP 8.5)重装依赖 + 全量测试:**162/162 通过**
