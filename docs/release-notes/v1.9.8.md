# v1.9.8

## 🔧 本次更新内容

> ⚠️ **强烈建议立即升级**：本版修复了「首页不显示商品」的严重问题（前台所有依赖货币换算的接口 500）。

### 1. 修复:首页/前台不显示商品(database cache 存坏 Eloquent 对象)

**现象**：店铺首页、商品列表等前台页面不显示任何商品；接口报
`CurrencyService::getEnabledCurrencies(): ... __PHP_Incomplete_Class returned`（500）。

**根因**：当 `CACHE_STORE=database` 时，Laravel 用 PHP `serialize()` 写入缓存。
`CurrencyService` 缓存的是 **Eloquent Collection 对象**（序列化数据含 `\0` 字节），
**MySQL 存取会破坏这些二进制数据** → 反序列化失败成 `__PHP_Incomplete_Class` →
类型错误 500。所有前台请求都经过 `ResolveDisplayCurrency` 中间件调用该服务，
导致整个前台不可用。

**修复**：
- `CurrencyService` 改为缓存**纯数组**（`toArray()` + `collect()` 包装，
  `getCurrency` 用 `hydrate` 构造模型）——数组序列化是纯 ASCII，任何缓存驱动都安全
- `ResolveSubsite` 同样从缓存 Merchant 对象改为缓存 `merchant_id` 标量
- **约定**：`database` 缓存驱动下不得缓存任何 Eloquent/ORM 对象

### 2. 修复:勾选导入上游商品价格恒 0

**现象**：从 acg-faka 等上游勾选导入的商品，售价全部是 ¥0.00。

**根因**：导入定价以 `factory_price`（上游成本价）为基准加成，但 acg-faka 上游的
`factory_price` 字段为 0（上游未配置成本）→ `0 × 1.1 = 0` → 价格恒 0。
而预览接口显示的售价（`price`）根本没有参与定价。

**修复**：
- 定价基准在 `factory_price <= 0` 时**回退到上游售价** `price`（按 `default_pricing_mode`
  加成）——acg-faka 商品导入后会有正确售价（如上游 ¥6.50 → 下游 ¥7.15）
- 已导入的 `price <= 0` 脏数据，在**下次同步/导入时自动重算**（正常的售价保护不受影响）

## ⬆️ 升级

> 在线更新：后台 → 在线更新 → 检查版本 → 一键更新即可（Git-based）。

```bash
# 手动方式
git pull origin main
php artisan route:clear && php artisan config:clear
php artisan cache:clear     # 清掉损坏的旧缓存(关键!)
# 重启 PHP-FPM(清 OPcache)
/etc/init.d/php-fpm-84 restart
```

升级后：
1. 刷新前台首页 → 商品正常显示
2. 若有已导入的 0 价商品 → 后台「货源对接 → 同步/导入」重新执行一次，价格自动修正
3. 浏览器 `Ctrl+F5` 强制刷新后台

**无数据库迁移。**
