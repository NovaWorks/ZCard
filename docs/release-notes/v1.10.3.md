# v1.10.3

## 🐛 修复:货源导入漏商品(勾选 16 个只导入部分/导入后仍显示"新货源")

**现象**:货源管理 → 拉取上游商品 → 勾选导入,显示"成功导入",但实际只有部分商品入库;
再次拉取时,已导入的商品仍显示"新货源(未对接)",客户反复导入仍不完整。

**根因**:
1. **导入依赖批量拉取匹配**:`importProducts` 会再次调用上游批量接口拉取商品并按 code 索引,
   再逐个匹配客户勾选的 code。若上游批量接口响应不稳定(分页缺失/超时/偶发返回不全),
   部分勾选 code 匹配不到 → 被 skip → 那些商品根本没入库,自然一直显示"新货源"。
2. **ZCard 驱动分页硬编码 bug**:`ZCardDriver::listProducts` 将 `has_more` 写死为 `false`,
   而上游 `/api/supply/products` 实际按 50/页分页返回。上游商品 >50 个时,
   预览/导入/同步都只取到第 1 页,第 2 页起的商品全部丢失。
3. **已对接判断类型严格比较**:`already_imported` 用 `in_array(..., true)` 严格比较,
   上游 code(数字/字符串)与本地存储类型不一致时会漏判。

**修复**:
1. **导入兜底**:批量拉取未匹配到 code 时,逐个调用驱动 `getProduct($code)` 精确拉取兜底,
   保证客户勾选的商品一定入库(不受批量接口响应不稳定影响)。
2. **ZCard 分页修正**:`has_more` 按 `(page * page_size) < total` 正确推导,>50 商品全量拉取。
3. **已对接判断类型归一**:上游 code 与本地存储统一转字符串再比较,兼容数字/字符串 code。

**回归测试**:新增 `tests/Feature/ImportProductsFallbackTest.php`(6 用例),
覆盖"批量返回不全时兜底补齐""ZCard 分页全量""导入后已对接标记正确"等场景。
