# v1.12.13

## 🐛 修复:支付回调地址(notify_url)相对路径导致易支付报「格式不正确」

### 根因

多个支付驱动(易支付/码支付/BEpusdt/EpuSdt/PayPal/Stripe)的 `namedUrl()` 用
`route($name, $params, false)`(第三个参数 `false` = 不生成绝对地址),输出的是
**相对路径**(如 `/api/payments/notify/epay`)。易支付等平台要求 `notify_url` 必须是
**完整 URL**(`https://域名/api/payments/notify/epay`),相对路径被判「通知地址格式不正确」。

### 修复

- **新增 `app/Payment/AbstractPaymentDriver.php`**(抽象基类):统一 `namedUrl()` 生成
  **绝对 URL**,并支持 `config['notify_domain']` 回调域名覆盖(参考 acg-faka 的
  `callback_domain` 设计——回调地址 = 可配置回调域名 + 固定路径)。
- **6 个驱动改为继承基类**:`EpayDriver` / `CodePayDriver` / `BEpusdtDriver` /
  `EpuSdtDriver` / `PaypalDriver` / `StripeDriver`,删除各自重复的 `namedUrl()`。
- **EpayDriver / CodePayDriver** 的 `getConfigFields()` 新增「回调域名(可选)」配置项,
  sysadmin 支付配置页动态渲染,无需改前端。
- `AlipayDriver` / `WechatPayDriver`(yansongda SDK 内部处理回调 URL)、`UsdtDriver`
  (无回调 URL)不受影响。

### 回调 URL 生成优先级

1. 通道配置 `notify_domain`(如 `https://kmigo.com`)→ 显式指定
2. 未配置 → 基于 `.env` 的 `APP_URL` 生成绝对 URL
3. 兜底 → 当前请求 URL

### 验证

- 易支付:默认 `notify_url = http://localhost:8092/api/payments/notify/epay`(绝对 URL);
  配置 `notify_domain` 后 = `https://callback.kmigo.com/api/payments/notify/epay` ✓
- 码支付:绝对 URL ✓
- `php artisan test`:176 通过 / 545 断言,无回归

### 部署提醒

1. 更新后确认 `.env` 的 `APP_URL` 为站点完整地址(如 `https://kmigo.com`)。
2. 若回调入口与站点域名一致,无需额外配置;不一致(CDN/独立公网入口)时在
   易支付/码支付通道配置里填「回调域名」。
