# v1.12.58

## 结算页首次验证码修复

- 修复首次打开结算页时，验证码请求与商品请求并发建立不同 Session，导致页面显示的第一个验证码提交后必然提示错误的问题。
- 验证码改为返回一次性的 `captcha_key` 和内联图片，下单时同时提交验证码与对应 key，后端不再依赖浏览器 Session Cookie 识别当前验证码。
- 单品下单和购物车批量下单均支持 `captcha_key` 校验，避免两条购买路径行为不一致。
- 保留旧客户端的 Session 验证方式，尚未刷新前台资源的客户端仍可继续使用。

## 前台请求稳定性

- 调整结算页初始化顺序：商品、购物车和支付渠道加载完成后再生成验证码，不再让首屏业务请求与验证码生成并发执行。
- 刷新验证码时同步清空旧输入和旧 key，避免用户提交图片与 key 不匹配的历史验证码。
- 增加验证码请求序号保护，连续点击刷新时只接受最后一次请求结果，避免较慢的旧请求覆盖新图片。
- 重新构建并提交前台生产资源，服务器更新后无需额外安装 Node.js。

## 回归测试

- 新增验证码接口返回 key 与内联图片的测试。
- 新增验证码按 key 校验且不依赖 Session 的测试。
- 新增携带 `captcha_key` 创建订单成功的完整接口测试。
