# v1.12.81

## 🐛 修复:同步任务统计显示与上游商品链接

**反馈**:

1. 「全部同步任务」弹窗宽度不足，任务后面的新增、更新、价格更新等统计会被截断；当统计值为 0 时，
   页面还会残留没有内容的分隔点；
2. 商品列表与订单详情中的「上游商品」链接使用对接 `code` 拼接 `/buy/{code}`，点击后进入错误页面。

**根因**:

1. 同步任务统计使用单行不换行布局，弹窗宽度只有 720px，并且部分统计项为 0 时被条件隐藏，
   但分隔符仍然保留；
2. acg-faka 的对接 `code` 是供 API 下单使用的随机标识，并不是公开商品页的数值 ID；不同版本或主题
   的公开链接还可能分别使用 `/item/{id}` 或 `?cid={分类ID}&mid={商品ID}`，不能根据 API code 猜测。

## 修复内容

- 将「全部同步任务」弹窗扩大到最大 1100px，并兼容窄屏 94vw；
- 允许进度条和统计信息按空间自动换行，完整显示已处理、新增、更新、价格更新及手动价跳过数量；
- 所有统计项在数值为 0 时仍明确显示，并由样式统一生成分隔符，不再出现空的 `· ·`；
- acg-faka 同步时从公开商品详情读取真实 `share_url`，兼容旧版查询参数链接与新版 `/item/{id}`；
- 每批同步只探测一次分享链接规则，再根据商品数值 ID 与分类 ID 生成本批链接，避免逐商品额外请求；
- 新增 `products.upstream_product_url` 字段，保存驱动确认过的真实链接；临时探测失败时保留上次正确值；
- 删除 acg-faka 的 `/buy/{code}` 猜测逻辑；无法确认真实链接时不再展示错误外链；
- 商品列表及订单详情统一读取已同步的真实链接，管理员显式配置的 `product_url_template` 仍保持最高优先级；
- 重新构建并提交管理端生产产物。

## 升级后操作

在线更新会自动执行数据库迁移。升级完成后，请进入「资管管理 → 货源管理」执行一次「全部同步」或
对应货源的「完整同步」，为已有商品写入真实上游链接。

同步完成后应确认：

- 「全部同步任务」弹窗可以完整看到所有统计数字，包括值为 0 的项目；
- 商品列表中的「上游商品」链接可以打开上游真实商品页；
- 若任务一直停留在「排队中」，确认 `php artisan queue:work` 常驻运行。
