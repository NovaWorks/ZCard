# v1.12.12

## 🐛 修复:验证码"输入正确仍报错"两大根因(线上排查结论)

### 根因 A:验证码图片与下单接口的 cookie 解密口径不一致

**现象**:验证码图片走 **web 组**(`vendor/mews/captcha` 硬编码 `->middleware('web')`),
带 `EncryptCookies`(cookie 加密写 session);下单接口走 **api 组**(`bootstrap/app.php`
只 prepend `StartSession`,无 `EncryptCookies`)。

当站点域名**不在 `SANCTUM_STATEFUL_DOMAINS`** 时(生产环境默认不在名单),
`EnsureFrontendRequestsAreStateful` 不会注入 `EncryptCookies` → api 组把图片请求写入的
**加密 cookie 当明文 session id** → 每次新建空 session → `Captcha::check()` 第一行
`session->has('captcha')` 为 false → 恒定报「验证码错误」。

**实测证据**(同一 cookie,仅改 Referer):
- Referer 命中名单 → `debug_answer: "9771"`(读得到)
- Referer 不在名单 → `no_captcha_in_session`(读不到)

**修复**:`bootstrap/app.php` 的 api 组 prepend 加入 `EncryptCookies`,使两组 cookie
加解密口径一致(本地 localhost 在名单内,此修复不影响本地;生产域名即刻生效)。

**验证**:修复后生产域名 Referer 场景 → 图片生成 → 读 session 答案 → 提交 batch → **201 下单成功**。

### 根因 B:验证码有效期仅 60 秒,收银台填单必然超时

**现象**:`config/captcha.php` trade 场景 `expire=60` 秒,验证码答案存 `Cache`
(`Cache::put(key, 答案, 60)`)。`check()` 用 `Cache::pull` 先判缓存是否存在,
缓存过期直接返回 false,**根本不比对用户输入**。收银台填联系方式/密码/支付渠道/优惠券/
靓号确认耗时常态超 60 秒,用户输入正确也报错。

**修复**:trade(及 default)场景 `expire` 60 → **600 秒(10 分钟)**。

**验证**:生成后缓存过期时间戳与当前相差 600 秒。

### 附带:移除 v1.12.11 的验证码排障调试后门

- 删除 `routes/api.php` 的 `DEBUG_CAPTCHA` 调试路由(`/captcha/debug-read` 及
  `/captcha/trade` 的 `debug_answer` 返回)。
- 删除 `.env` / `.env.example` 的 `DEBUG_CAPTCHA` 配置。
- 该开关仅作线上排障定位用,已确认根因,必须移除,避免验证码答案明文外泄。

### 已知遗留(非本次范围,安全增强)

- 场景隔离不彻底:mews `captcha_check()` 只收 1 参,`CaptchaService::verify()` 的
  `$scene` 被丢弃,register/login/trade 共用同一 session 验证码。当前 register/login
  验证码默认关闭(`captcha_register=false, captcha_login=false`),无实际风险,后续可改。
