# v1.12.83

## 🐛 修复：货源同步卡死、旧队列进程与上游错误不可见

**客户反馈**：

- `php artisan queue:work` 报错
  `Undefined property: App\Supply\Dto\UpstreamProduct::$productUrl`；
- 增量/全量同步任务长期停留在“同步中”，失败前管理员只能看到任务卡住；
- 上游接口被 IP 白名单、WAF、限流或网络错误拦截时，后台没有可操作的失败原因；
- 已经卡住的同步任务无法在“全部同步任务”弹窗中按任务取消；
- 在线更新后 `/api/admin/supply-sources/drivers` 偶发返回 `Server Error`。

**根因**：

- 在线更新只替换磁盘代码，没有重启长驻 `queue:work`，导致旧 DTO 与新同步服务在同一 worker 中混用；
- PHP-FPM 的 OPcache 在部分服务器关闭时间戳校验，在线更新后仍可能缓存旧接口/驱动类；
- 同步任务缺少持续心跳、执行阶段、失败回调和过期回收，worker 被终止后任务记录不会自动进入终态；
- 任务最长运行时间大于队列默认 `retry_after`，存在任务尚未结束就被再次领取的风险；
- 上游 HTTP 错误被压缩成普通异常，后台无法区分认证、IP 限制、WAF、限流、DNS、TLS 和超时。

## 修复内容

- 在线更新和回退完成后自动重置 PHP OPcache，并发送 `queue:restart` 信号；
- 队列探针同时上报网站版本、worker 启动版本和启动时间，后台直接提示版本不一致；
- 对旧 worker 中没有 `productUrl` 属性的 DTO 增加兼容读取，避免同步直接崩溃；
- 同步任务新增心跳、当前阶段/页码、阶段进度、取消请求、错误码/上下文和 worker 版本；
- 运行中任务采用“取消中 → 已取消”状态机，排队任务可立即取消；全部任务弹窗支持按任务 ID 取消；
- 已取消、已超时任务使用条件更新保护，旧 worker 的迟到结果不能覆盖为成功或失败；
- 看门狗每分钟回收长期无心跳任务，打开任务列表或再次同步前也会主动回收，避免永久占用防重锁；
- 增加 worker 超时失败回调，将异常退出的任务收口为失败/超时并保留诊断；
- 统一上游错误分类，后台显示 HTTP 401/403/404/429/5xx、IP 白名单/WAF、DNS、TLS、连接和响应超时；
- 错误上下文只展示脱敏后的上游主机/路径和 HTTP 状态，不保存签名、密钥、Cookie 或完整响应；
- acg-faka 库存接口被屏蔽时不再静默当作无限库存，而是终止同步并显示真实限制原因；
- 将货源同步任务最长运行时间调整为 900 秒，数据库/Redis/Beanstalkd 默认 `retry_after` 调整为 960 秒；
- `drivers` 元数据接口在检测到 PHP 运行时混版时返回明确的 PHP-FPM 重启提示；
- 历史 `productUrl` 裸错误在货源列表中转换为可操作的 Supervisor 重启提示；
- “全部同步任务”弹窗展示当前阶段、最后活动时间、worker 版本、错误码和上游端点；
- 重新构建并提交管理端生产产物。

## 升级后必须操作

本版本包含数据库迁移，在线更新会自动执行。由于从 `v1.12.82` 升级时，执行更新请求的仍是旧版
更新控制器，因此本次升级完成后必须手动重启一次 PHP-FPM 和 Supervisor：

```bash
cd /www/wwwroot/ZCard
php artisan optimize:clear
php artisan queue:restart
supervisorctl restart zcard-queue:*
```

然后在宝塔“软件商店 → PHP → 服务”中重启 PHP-FPM；也可按实际 PHP 版本执行：

```bash
/etc/init.d/php-fpm-84 restart
```

如果 Supervisor 中的进程名称不是 `zcard-queue`，请在面板中重启实际的 ZCard 队列守护进程。
后续版本在线更新会自动重置 OPcache 并平滑重启队列。

重启完成后，进入“资管管理 → 货源管理 → 全部同步任务”确认：

- 队列状态为正常且网站版本与 worker 版本均为 `1.12.83`；
- 旧的卡住任务已进入超时/已取消终态；
- 重新执行完整同步后任务阶段和最后活动时间持续更新；
- 上游被屏蔽或接口异常时，任务中出现明确错误码和处理提示。
