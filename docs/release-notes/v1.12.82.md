# v1.12.82

## 🐛 修复:同步时自动删除失效的上游商品

**客户反馈**:

上游商品已经失效、下架或删除，但执行商品同步后，对应商品仍然保留在本站商品列表中。

**根因**:

- 同步服务遇到上游明确标记为失效的商品时，只将本地商品设为隐藏，没有执行删除；
- 完整同步发现本地商品已不在上游商品集合中时，同样只标记隐藏；
- 定时任务统一使用“增量同步”标识，但 acg-faka 和 ZCard 驱动实际返回的是完整商品快照，
  原流程未利用该快照做失效商品对账。

## 修复内容

- 上游明确标记失效的已导入商品现在会执行软删除，新返回的失效商品不再导入；
- 完整同步会软删除已不存在于上游完整商品集合中的本地商品；
- acg-faka 和 ZCard 驱动即使由定时增量任务触发，也会按完整快照自动对账失效商品；
- DujiaoNext 等真正支持增量商品列表的驱动，不会因为本次增量结果未包含某商品而误删；
- 完整对账前校验上游分页总数，上游返回不完整时终止任务，不执行批量删除；
- 同一上游商品后续恢复有效时，会自动恢复原本的软删除记录；
- 历史订单和待处理订单继续可以读取软删除商品的原有信息；
- 同步任务增加“删除”数量统计，便于管理员核对本次清理结果；
- 重新构建并提交管理端生产产物。

## 升级后操作

在线更新会自动执行数据库迁移，为同步任务补充 `deleted_count` 统计字段。

升级完成后，请进入“资管管理 → 货源管理”对对应货源执行一次“完整同步”，清理已在上游失效或删除的历史商品。

同步完成后应确认：

- 失效商品不再出现在正常商品列表中；
- 同步任务弹窗可以看到本次“删除”数量；
- 若任务一直停留在“排队中”，确认 `php artisan queue:work` 常驻运行。
