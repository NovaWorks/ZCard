# v1.12.96

## 🐛 修复：根前端生产构建依赖 fonts.bunny.net 可用性（issue #20）

**报告**：[#20](https://github.com/NovaWorks/ZCard/issues/20) 指出根目录 `vite.config.js`
使用 `laravel-vite-plugin/fonts` 的 **bunny** 提供方引入 Instrument Sans 字体，构建时会从
`https://fonts.bunny.net/css2?family=Instrument+Sans:wght@400;500;600` **联网下载字体 CSS 与
字体文件**；CDN 不可达（受限网络 / CDN 故障 / DNS 问题）时 `pnpm build` 在转换任何模块前
直接退出 1（`[plugin laravel:fonts]`）。依赖已装全的 CI / 生产环境仍被外部 CDN 卡发布，
且本地成功可能只是未版本化缓存掩盖。

**核实**：属实。`laravel-vite-plugin` 3.1.3 源码中 bunny 提供方硬编码
`fetch("https://fonts.bunny.net/css2…")`（构建时网络请求）；而 **fontsource** 提供方解析
`@fontsource/{family-slug}` 包并 `readFileSync` 读取本地字体文件，零网络依赖。

**修复内容**：

- `vite.config.js`：`bunny('Instrument Sans', { weights: [400,500,600] })`
  → `fontsource('Instrument Sans', { weights: [400,500,600] })`；
- `package.json`：devDependencies 新增 `@fontsource/instrument-sans: ^5.3.0`；
- `pnpm-lock.yaml`：固定 `@fontsource/instrument-sans@5.3.0`（按 issue 建议锁定到锁文件）。

**验证**：清除 `node_modules/.cache/laravel-vite-plugin/fonts` 缓存后构建成功，字体文件
（woff2/woff，400/500/600）全部由本地包产出；生成的 CSS 字体族仍为 `"Instrument Sans"`
（与 `resources/css/app.css` 的 `--font-sans` 一致），设计不变。`public/build` 属 gitignore
产物，不入库。

**影响范围**：仅根项目（`composer dev` / `vite build`）构建；业务代码、数据库、两套后台
（sysadmin/storefront）均未改动。

## 升级与使用

- 通过后台「在线更新」或 `git pull && composer install --no-dev` 升级；**无数据库变更**；
- 生产 / CI 需执行 `pnpm install`（拉取新增的 `@fontsource/instrument-sans`）后再
  `pnpm run build`；此后构建不再需要访问 fonts.bunny.net。
