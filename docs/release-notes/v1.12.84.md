# v1.12.84

## 🐛 修复：Chatwoot / Crisp 第三方客服代码不执行

**客户反馈**：

- 在后台“设置 → 在线客服”粘贴 Chatwoot、Crisp 等平台提供的 JavaScript 安装代码后，前台没有出现客服气泡；
- 配置已保存且公共设置接口可以读取，但浏览器前台没有实际加载第三方客服 SDK。

**根因**：

- 前端把包含完整 `<script>...</script>` 标签的安装代码直接写入 `script.textContent`，浏览器会把标签本身当成 JavaScript 解析并报语法错误；
- 严格内容安全策略只允许同源脚本，Chatwoot / Crisp 的内联初始化代码和外部 SDK 地址都会被 CSP 拦截；
- 原始客服安装代码直接随公共设置 JSON 返回，扩大了不必要的公开配置范围。

## 修复内容

- 新增同源客服脚本端点 `/api/settings/service-widget.js`，统一编译并输出站长配置的客服安装代码；
- 支持直接粘贴 Chatwoot / Crisp 官方完整 `<script>` 安装代码，也兼容历史纯 JavaScript 配置；
- 正确剥离脚本标签，并按浏览器规则加载显式的外部 SDK 脚本；
- 仅允许 HTTPS 或同源外部脚本，拒绝 `javascript:` 等危险脚本地址；
- 从客服代码中提取 HTTPS 来源，只在商城页面的 CSP 中精确放行对应脚本、样式、字体和 iframe 来源；
- 保持 `script-src` 不启用 `unsafe-inline`，避免为兼容客服插件而降低全站脚本安全边界；
- 公共设置接口不再返回原始客服代码，只返回 `script_configured` 状态；
- 前端改为从同源端点加载客服脚本，并通过页面标记保证只加载一次；
- 更新中英文后台说明，明确支持完整安装代码、要求 HTTPS 且只能粘贴可信平台代码；
- 重新构建并提交 storefront、sysadmin 生产产物。

## 升级与使用

本版本不包含数据库迁移。升级后进入“设置 → 在线客服”：

1. 开启“启用客服浮窗”；
2. 将 Chatwoot 或 Crisp 后台提供的完整安装代码粘贴到“第三方客服代码”；
3. 保存设置并强制刷新商城前台；
4. 确认右下角出现第三方平台原生客服气泡。

外部 SDK 地址必须使用 HTTPS。第三方客服代码具有在商城页面执行脚本的权限，只能粘贴来自可信客服平台的官方代码。
