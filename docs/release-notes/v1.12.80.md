# v1.12.80

## 🐛 修复:上游渠道加价未落到商品售价

**反馈**:资管管理中为上游渠道设置加价比例并确认后，同步任务没有调整商品售价；
商品列表中的「预选加价/成本」也一直显示 0。

**根因**:

1. 历史版本中，商品编辑会统一写入 `price_manual=true`。渠道调价触发的同步任务仍会保护这些
   手动价，因此任务虽然完成，商品售价却不会重新计算，旧任务也没有展示跳过数量；
2. `draft_premium` 的真实含义是买家「预选卡密」时的额外费用，与上游渠道加价无关，原列名
   「预选加价/成本」容易让人误以为它应展示渠道加价；
3. v1.12.79 新增的上游价格快照在部分商品尚未重新同步时为空，商品列表缺少明确的待同步提示。

## 修复内容

- 货源列表新增「覆盖调价」操作：管理员确认后按当前渠道规则执行全量重新定价，覆盖历史手动价，
  并将这些商品恢复为后续自动跟随上游价格；
- 常规同步仍保留手动价保护，任务详情新增「手动价保护跳过 N」统计，不再出现任务完成但原因不可见；
- 渠道定价设置变更后派发的全量任务，会真正验证并更新未受手动价保护的商品售价；
- 商品列表新增「上游价格/加价」信息，按「本地售价 - 上游售价」展示渠道加价；上游价格快照
  尚未生成时显示「待同步」，平价商品显示「平价」；
- 将旧列名改为「预选卡加价/成本」，明确它只表示预选卡密费用与成本，不代表上游渠道加价；
- 同步任务新增覆盖调价标记和手动价跳过计数，升级时由数据库迁移自动补齐。

## 受影响客户处理

升级后进入「资管管理 → 货源管理」，在对应上游渠道点击「覆盖调价」并确认。任务完成后：

- 「价格更新 N」应大于 0（若新旧计算结果相同则可为 0）；
- 「手动价保护跳过」应为 0；
- 商品列表「上游价格/加价」应显示当前上游售价和实际渠道加价；
- 「预选卡加价」保持原配置，不会被渠道重新定价修改。

同步依赖队列进程，若任务一直停留在「排队中」，请先确认 `php artisan queue:work` 常驻运行。
