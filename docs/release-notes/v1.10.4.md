# v1.10.4

## 🐛 修复:导入商品 code 串号导致"已导入仍显示新货源"(真实根因)

**现象**:货源管理 → 拉取上游商品 → 勾选导入,显示"成功导入 N 个",但再次拉取时
部分商品仍显示"新货源(未对接)";商品列表中部分记录名称与来源商品不符。

**真实根因**(在 kmigo.com 生产环境定位):
`SupplySyncService::upsertProduct` 用 `orWhere('slug', Str::slug(name))` 兜底匹配已存在商品。
上游不同商品(如「美区Gemini」与「随机Gemini」)生成的 slug 相同,导致:
- 新商品被误绑到**旧记录**上(走 update 分支),`upstream_product_code` 保持旧值 → **新 code 未入库**
- 旧记录的 name/描述被新商品覆盖,但 code 没变 → 记录名实不符
- 再次拉取时,上游新商品的 code 在本地匹配不到 → 始终显示"新货源"
- import 返回的 `imported` 计数包含误绑更新,所以显示"成功导入"但实际新商品没入库

**修复**:`upsertProduct` 移除 slug 兜底匹配,**只按 `upstream_product_code` 精确匹配**。
同一货源下上游 code 是稳定唯一键;slug 冲突由 `uniqueSlug` 自动加序号处理,不会误绑。

**回归测试**:`ImportProductsFallbackTest::test_similar_names_do_not_cross_match_codes` ——
模拟「美区Gemini(新)」与「随机Gemini(已导入)」slug 相同,修复前测试红(误绑),
修复后绿(美区Gemini 新建独立记录,code 不串号)。

## ⬆️ 升级

在线更新:后台 → 在线更新 → 一键更新。**无数据库迁移**。

**已受影响数据自愈方式**:修复后,对每个受影响的货源重新「拉取商品 → 勾选导入」一次即可:
- 被误绑的新商品 code 现在会**新建独立记录**(按精确 code)
- 旧记录的 name/描述会在下次同步/导入时被**自动修正**为 code 对应的正确名称

> 无需手动处理数据库,重新导入即自愈。
