# v1.12.47

## 🐛 修复:订单倒计时 484:39——后端时间改为带时区 ISO8601

**现象**:修复 +Z 后倒计时反而显示 8 小时(484:39),比之前更糟。

**根因**:线上环境时区口径与预期不符。`toDateTimeString()` 返回**无时区标记**
的字符串(UTC 环境=UTC 时间,非 UTC 环境=本地时间),前端无论按本地解析还是
强制 +Z 都可能在另一类环境出错 —— **根本问题是无时区信息,前端无法判断基准**。

**修复**:
- **后端**(`OrderService::myOrders/searchOrders` 的 created_at/paid_at):
  `toDateTimeString()` → **`toIso8601String()`**(如 `2026-08-11T05:30:32+00:00`,
  带时区偏移)——无论线上 APP_TIMEZONE 如何配置,前端都能正确解析。
- **前端 PayResult**:倒计时直接 `new Date(createdAt)`(ISO 自动解析,
  移除手动 `+Z`)。
- **前端展示兼容**:MyOrders 的 fmtDate 适配 ISO(截取 `YYYY-MM-DD HH:mm`)。
  OrderQuery/UserCenter 的 fmtDate 本就 slice+replace,无回归。
