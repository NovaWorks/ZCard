# v1.1.9

## 🔒 安全修复:.env 不再进 git(避免被 git pull/reset 覆盖)

### 问题

v1.1.3 曾把 `.env` 提交进仓库(为了让 clone 后开箱即用),但这导致严重隐患:
- **`git pull` / `git reset --hard` 会覆盖用户已配置的真实 `.env`**(数据库密码、APP_KEY、CARD_ENCRYPTION_KEY 全丢)
- 实际已造成线上事故:用户 `git reset --hard` 后 `.env` 被重置,数据库凭据丢失

### 修复

1. **`.env` 从 git 跟踪移除**(`git rm --cached .env`),重新加入 `.gitignore`
2. **`EnsureInstalled` 中间件新增 `ensureEnvFile()`**:.env 不存在时自动从 `.env.example` 复制一份(clone 后首次访问自动创建),**已存在则绝不覆盖**
3. 保留 `.env.example` 作为模板(含详细注释的安全默认值)

### 行为

| 场景 | v1.1.3~v1.1.8 | v1.1.9 |
|---|---|---|
| clone 后首次访问 | `.env` 来自仓库(空凭据) | `.env` 自动从 `.env.example` 复制 |
| 安装向导配置后 | ❌ `git pull` 可能覆盖 | ✅ `git pull` 永不覆盖(.env 不在 git) |
| `git reset --hard` | ❌ 配置全丢 | ✅ `.env` 不受影响 |

## 🔧 文档路径脱敏

v1.1.8 release notes 和部署指南暴露了用户服务器真实路径,已全部替换为 `<项目目录>` / `<你的项目目录>` 等通用占位符。

## ⬆️ 升级

> ⚠️ **本次升级必须用命令行**(在线更新此时可能仍有 git 问题)。

```bash
cd <你的项目目录>

# 解决 git dubious ownership(如果之前没做过)
git config --global --add safe.directory "$(pwd)"

# 备份你的 .env(防止意外)
cp .env .env.mybackup

# 拉取最新代码
git pull origin main

# .env 不会再被覆盖了,但确保它存在(应该还在)
test -f .env && echo "✅ .env 安全" || cp .env.example .env

# 权限 + 缓存
chown -R www:www storage bootstrap/cache vendor
rm -f bootstrap/cache/*.php
php artisan optimize:clear
/etc/init.d/php-fpm-84 restart
```

无数据库变更,无前端变更。
