# v1.12.60

## 商品详情与付款后使用说明

- 商品设置正式区分“公开商品详情”和“付款后使用说明”：公开详情在付款前展示，付款后使用说明仅在订单支付成功后展示。
- 付款后使用说明改用富文本编辑器，可填写激活步骤、下载说明、登录方法、代码块、图片、链接和注意事项。
- 下单时生成付款后使用说明快照，商品后续修改、下架或删除不会改变历史订单中的说明。
- 商品公开接口不再返回付款后使用说明，避免未付款用户或供货目录提前获取受保护内容。
- 商品详情和付款后说明在服务端进行 HTML 清理，Storefront 展示时再通过 DOMPurify 二次过滤，降低存储型 XSS 风险。
- 支付结果、我的订单和游客查单统一展示付款后使用说明，并支持“没有卡密、只有使用说明”的数字商品。
- 发货邮件增加纯文本使用说明，同时保留一次性通知和重复发货保护。

## 四种商品履约方式

- 新增自动卡密、固定内容、人工发货和上游履约四种商品履约方式。
- 自动卡密继续使用原有卡密库存和 `status/delete` 用后处置策略，不改变已有商品行为。
- 固定内容商品无需维护卡密库存，支付成功后自动发送下单时保存的固定内容快照。
- 人工发货商品支付后进入待发货状态，管理员可在订单列表填写订单专属内容并完成发货。
- 上游商品自动锁定为上游履约，避免在本地误选卡密或固定内容流程。
- 履约写入通过统一事务和订单行锁执行，重复支付通知、上游回调或人工提交不会产生重复发货内容。
- 商品列表和缺货筛选按照履约方式计算库存，并兼容升级前已经存在的上游商品数据。

## 采集商品与公开详情同步

- dujiao-next 优先同步多语言 `content` 作为公开商品详情，为空时回退到 `description`。
- dujiao-next 货源设置新增内容语言选项，可选择简体中文、繁体中文或英文。
- acg-faka 优先使用公开 `description` 字段，不再把其他展示字段误当成付款后教程。
- 货源设置新增“同步公开详情”开关；关闭后定时同步不会覆盖运营人员在本地修改的商品详情。
- 新导入的上游商品自动标记为上游履约，公开详情和付款后教程继续使用不同的权限边界。
- dujiao-next 和 acg-faka 原版供货协议未提供付款后教程时保持空值，不抓取管理端或用户私有接口。

## ZCard 供货协议与回调

- ZCard 供货商品目录只返回公开商品详情，不返回付款后教程。
- 同步下单响应、订单轮询和异步回调统一使用 `fulfillment` 结构返回履约类型、发货状态、发货内容和付款后说明。
- ZCard 作为下游时，可把上游返回的发货内容和付款后说明在同一事务中写入本地订单。
- 支持上游只返回使用说明、不返回卡密的已完成履约结果。
- 新增供货异步回调发送服务，使用四头 HMAC 签名并校验回调时间窗口。
- 回调地址继续执行 SSRF 防护；缺少签名头、签名错误或时间过期的通知会被拒绝。
- 供货回调和人工发货都复用统一幂等履约服务，避免并发通知造成二次发货。

## 管理端与 Storefront

- sysadmin 商品抽屉新增履约方式选择，并根据类型显示卡密设置、固定内容、人工发货提示或上游说明。
- sysadmin 订单列表新增发货状态和履约类型展示，人工订单可直接提交一次性发货内容。
- sysadmin 货源设置新增公开详情同步开关和 dujiao-next 内容语言配置。
- Storefront 对待人工发货、待上游发货和其他处理中订单显示对应状态提示。
- 已发货订单才开放评价入口，避免顾客在尚未收到内容时提前评价。
- 订单发货内容展开控件补充可访问性状态和关联属性。
- 重新构建并提交 sysadmin 与 storefront 生产资源，服务器在线更新后无需安装 Node.js。

## 数据迁移与兼容性

- 商品表新增履约类型字段，默认值为自动卡密，现有本地商品升级后保持原有行为。
- 订单表新增履约类型、付款后使用说明和固定发货内容快照字段。
- 数据迁移自动将已有上游商品及对应订单标记为上游履约。
- 保留现有 `leave_message`、`delivery_message` 和 `delivery_mode` 字段，避免破坏旧数据、旧管理端和已有插件。
- 本版本未修改 Composer 依赖或锁文件，在线更新不会引入依赖版本变化。
