# v1.12.49

## 🐛 修复:客户环境仍报 Data too long for column 'name'(截断长度保守化)

**现象**:v1.12.48 发布后客户仍报同样的错。原因:线上**未执行迁移**
(products.name 仍为 varchar(150))或**代码未更新**到 v1.12.48
(截断 500 对旧库 150 无效)。

**修复**(兜底,任何环境都不再报错):
- `SupplySyncService` 同步/更新商品时,`name` 与 `slug` **统一截断到 145**
  —— 兼容未迁移的旧库 varchar(150);已执行迁移(500/250)也不受影响。
- 迁移(150→500/250)保留:扩容供需要完整名称的场景,但**不再是必选**。

**部署**:
1. **必须更新后端代码**(截断逻辑生效的关键)。
2. 迁移可选执行:`php artisan migrate`(执行后字段扩容,不执行也不报错)。

## 验证

- `SupplySyncServiceTest` 超长商品名用例更新:name/slug ≤ 145,同步成功。
- 全量 212 通过 / 664 断言。
