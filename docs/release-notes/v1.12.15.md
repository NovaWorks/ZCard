# v1.12.15

## ✨ 新增:支付渠道自定义交易手续费 + 易支付 MD5/RSA 双模式 + 回调域名动态化

### 1. 支付渠道自定义手续费(任意渠道)

在支付通道配置里可为每个渠道设置交易手续费:

- **承担方**:商户承担(应付金额不变,手续费从商户实收扣) / 客户承担(加到应付金额)。
- **类型**:百分比(如 1.5 = 1.5%) / 固定金额(如 0.5 元)。
- 手续费记录到支付流水(`payments.fee`),便于对账;商户承担时实收 = charged_amount - fee。

**数据变更**:
- `payment_channels` 新增 `fee_bearer`(merchant/customer)。
- `payments` 新增 `fee`(手续费,分)。

**验证**:百分比+客户承担 ¥6.50→¥6.63;商户承担金额不变仅记 fee;固定金额 ¥6.50→¥7.00。

### 2. 易支付 MD5 / RSA 双模式(889 平台默认 RSA)

- **通道配置可切换签名方式**:MD5(V1 传统易支付) / RSA(V2 新版易支付,889 默认)。
- **RSA 需填商户私钥**(「商户密钥/私钥」字段) + **平台公钥**(用于回调验签)。
- `verifyCallback` **优先用回调自带的 `sign_type` 字段**判断验签算法,其次回退通道配置,
  避免配置与回调不一致时用错算法导致验签失败。

**验证**:MD5 下单+回调入账 ✓;RSA 下单+回调入账 ✓。

### 3. 回调地址用当前运行域名(非 env)

参考 acg-faka(`$_SERVER['HTTP_HOST']`):回调地址默认用**当前请求的 scheme+host** 生成
(部署到哪个域名就自动用哪个域名),不再依赖 env 的 APP_URL。仅当回调入口与站点域名不一致
(CDN/独立公网入口)时才需在通道配置填「回调域名」。

**验证**:`Host: kmigo.com` 请求 → notify_url = `https://kmigo.com/api/payments/notify/epay`。

### 4. 易支付回调路由 GET/POST 兼容

易支付(889)文档明确异步通知走 **GET**(部分平台 POST)。原路由 `Route::post` 导致 889
GET 回调返回 405 → 充值不到账。已改 `Route::any` 兼容两种方式。

**验证**:889 规范 GET 回调 → `success` → 充值单 paid → 余额入账 ✓。
