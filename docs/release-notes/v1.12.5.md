# v1.12.5

## 🐛 修复(手机 H5 前端 + 后端库存/会话)

### 1. 自定义支付无法输入数字
充值页「自定义金额」的 `<input>` 原本嵌套在 `<button>` 内——HTML 非法结构,
移动端点击输入会被外层按钮的 click 吞掉导致无法输入。已改为 `<div>` 容器 + `@click.stop`。

### 2. 拉取上游产品库存全为 0
商品列表/详情接口此前用 `withCount(cards)` 统计库存,上游商品无本地卡 → 恒为 0。
已改为 `availableStock()`(上游商品读 `stock_cache`,本地商品数未用卡密)。
新增回归测试 `test_upstream_product_stock_uses_stock_cache`(含无限库存 -1 场景)。

### 3. 默认显示货币为美元,手机首访却显示人民币
`prefs.load()` 只更新 Pinia store 状态、未写回 `localStorage`,
而请求拦截器从 `localStorage` 读货币 → 手机新访客无值 → 后端回退基础货币。
且原逻辑先占位 base 货币导致后台默认货币永远不生效。
已修复:货币优先级改为「用户已保存 > 后台默认 > 基础货币」,并在 load 末尾统一写回
`localStorage`。实测:默认 USD + 全新访客 → 商品显示 `$` 正确。

### 4. 验证码明明写对却提示错误(生产严重)
**根因**:`.env` 中 `SESSION_DOMAIN` 出现两次(`null` 后又被 `localhost` 覆盖),
导致 Session Cookie 的 `domain=localhost` —— 真实浏览器访问站点域名时不发送该
Cookie,验证码图片请求与下单请求各用独立 session,校验必失败。
**影响面**:所有依赖 session 的功能(验证码、登录态、购物车)在跨请求时都受影响。
已修 `.env.example`(删除重复行);**生产环境请在服务器将 `.env` 中的
`SESSION_DOMAIN` 保留为 `null`(只保留一行),再重启 PHP 生效**。

### 5. 手机 H5 购物车按钮空白(疑似缓存)
当前代码按钮文字/样式正常(实测渲染无误),疑为手机浏览器缓存旧版前端产物。
发布本版本后,请让手机用户**强制刷新/清除缓存**加载新产物。

## ⚠️ 生产部署必须操作

1. 编辑服务器 `.env`:删除重复的 `SESSION_DOMAIN=localhost`,只保留 `SESSION_DOMAIN=null`
   (或改为你的域名)。然后 `php artisan config:clear` + 重启 PHP-FPM。
2. 后台 → 在线更新 → 更新到 v1.12.5。
