# v1.12.92

## 🐛 修复：nginx 把客服脚本端点当静态文件拦截 → 线上客服不加载

**客户反馈**：线上站点（nginx 部署）已更新到最新版本，客服（Chatwoot/Crisp）仍不显示。

**根因**：客服脚本同源端点路径为 `/api/settings/service-widget.js`，**以 `.js` 结尾**。许多 nginx 配置带有「`.js`/`.css` 等后缀按静态文件处理」的 location 规则，导致该 API 路径被 nginx 直接判 404（根本不到达 PHP）。本地/开发环境由 Laravel 全权路由，无法复现——线上表现为：设置接口正常（enabled=true、script_configured=true）、CSP 正常放行全部客服域名，唯独脚本端点 404，前台注入的 `<script>` 加载失败。

**修复内容**：

- 新增无扩展名同义端点 **`/api/settings/service-widget-script`**（前端默认改用此路径），旧 `/api/settings/service-widget.js` 保留兼容；
- 前台 `ServiceWidget.vue` 改用新端点；
- 回归测试改为同时断言新旧两条端点均可用。

## 升级与使用

- 通过后台「在线更新」或 `git pull && composer install --no-dev` 升级；无数据库变更。
- 升级后**强制刷新（Ctrl/Cmd+Shift+R）前台页面**即可看到客服气泡。
- 验证命令：`curl -s https://你的域名/api/settings/service-widget-script` 应返回 JS 代码而非 404。
- 若暂不升级，可在 nginx 中让 `/api/` 路径绕过静态规则（在静态 location 之前加）：
  ```nginx
  location ^~ /api/ {
      try_files $uri $uri/ /index.php?$query_string;
  }
  ```

## 附带改进（与上版同步）

- 客服白名单支持通配写法：`*.example.com` 与 `example.com` 等价，均放行该主域名的任意层级子域名（`a.example.com`、`b.c.example.com`）；CSP 生成 `*.host` 通配源；默认白名单包含 Crisp 全套官方域名与 Chatwoot 官方域名，设置页说明已同步更新。
