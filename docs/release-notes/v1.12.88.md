# v1.12.88

## 💰 用户管理余额修改：恢复编辑能力 + 强制账单流水

**客户反馈**：后台「用户管理」把某用户余额改成 0，保存后余额仍为 20，且不清楚余额变动是否有流水记录。

**背景**：v1.12.85 安全整改为修复「管理员直改余额自肥且无流水」的漏洞（H2），移除了 `PUT /api/admin/users/{id}` 的 `balance` 字段——余额只能经 `POST /api/admin/bills/adjust` 调账。前端表单当时仍保留余额输入框，导致"保存了但后端不生效"的困惑。

**本次修复（恢复易用性，同时保留安全约束）**：

- `Admin/UserController::update` 重新接受 `balance` 字段，但**不再直写 `users.balance`**：计算新旧差额后经 `BillService::record` 入账——
  - 每笔变动自动生成**账单流水**（账单管理可查，含操作人 `admin_id`、变动后余额快照、类型收入/支出）；
  - 行锁 + 余额不足校验（差额大于现有余额会被拒绝）；
  - **禁止修改本人余额**（与 `bills/adjust` 同一口径，防自肥）；
  - `min:0` 校验，不允许负余额；
  - 入账失败时不落任何用户字段（一致性）。
- 前端用户编辑表单余额项增加提示：「修改余额将自动生成账单流水(账单管理可查),不允许修改本人余额」。
- 新增/更新回归测试 4 个：改小余额产生支出流水（含操作人）、改大产生收入流水、自改本人余额 422、负余额 422。

## 升级与使用

- 通过后台「在线更新」或 `git pull && composer install --no-dev` 升级；无数据库变更。
- 历史操作说明：v1.12.85–v1.12.87 期间用户管理里的余额修改确实被后端忽略（这是当时安全整改的预期行为）；升级到本版后即恢复可编辑，且每一次修改都有流水可查。
