# v1.1.2

## 🐛 关键修复:未安装时访问首页 500 → 自动跳转安装向导

### 问题

客户 clone 仓库并 `composer install` 后,直接访问首页 `/` 会得到 **500 错误**(空响应),而不是被引导到安装向导。这导致新用户无法完成首次安装,必须手动输入 `/install` 才能开始。

连 `/install` 页面本身也打不开 —— 同样 500。

### 根因

访问 `/` 时,请求会先经过 web 中间件组 → **`StartSession`** 中间件 → session driver 是 `database` → 查 `sessions` 表 → **表不存在(尚未 migrate)→ PDOException → 500**。整条链路没有任何"未安装 → 跳转安装向导"的全局兜底。

### 修复

新增全局中间件 `EnsureInstalled`(在所有中间件之前执行):

- **已安装**(锁文件 `storage/app/installed` 存在):直接放行,零行为变化。
- **未安装**:
  - 先把 session/cache/queue driver **降级为内存驱动**(array),避免 `StartSession` 等 middleware 碰数据库而崩溃 —— 这是让 `/install` 页面能正常加载的关键。
  - 放行安装向导本身(`/install`、`/api/install/*`)及静态资源(`css/js/fonts/storefront/admin`)。
  - 其余浏览器请求 **302 跳转 `/install`**。
  - API 请求返回 **503 JSON**(含 `install_url`,前端可据此引导)。

### 行为对比

| 场景 | v1.1.1 及之前 | v1.1.2 |
|---|---|---|
| 未安装访问 `/` | ❌ 500 空响应 | ✅ 302 跳转 `/install` |
| 未安装访问 `/install` | ❌ 500(StartSession 崩) | ✅ 正常加载安装向导 |
| 未安装访问任意 API | ❌ 500 | ✅ 503 JSON 提示未安装 |
| 已安装访问 `/` | ✅ 正常 | ✅ 正常(零变化) |
