# v1.12.50

## 🐛 货源同步 name 超长:改为运行时读取字段长度自适应截断

**现象**:线上已更新 v1.12.49 仍报 `Data too long for column 'name'`。
原因:代码更新后**未重启 PHP-FPM**(OPcache 缓存旧字节码,截断逻辑未生效);
且写死截断长度(145/500)无法同时适配"已迁移/未迁移"两种库。

**修复**(`SupplySyncService`):
- **运行时读取 `products.name` / `slug` 字段实际长度**(`SHOW COLUMNS` 解析
  varchar(n)),按实际长度截断 —— 迁移过(500)/未迁移(150)都精确适配,
  任何环境不再报错。
- `last_error` 展示截断到 500 字符(避免货源管理界面被长 SQL 刷屏)。

**部署(客户环境必做)**:
```bash
cd <项目目录>
git pull                                   # 更新到 v1.12.50
php artisan migrate --force                # 可选(建议执行,扩容字段)
# ⚠️ 关键:重启 PHP-FPM(清 OPcache,否则仍跑旧代码)
/etc/init.d/php-fpm-84 restart             # 或宝塔:软件商店→PHP-8.4→重启
```
重启后重新同步货源即可;若仍报错,先执行 `php artisan optimize:clear` 再试。
