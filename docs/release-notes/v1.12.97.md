# v1.12.97

## 🐛 修复：sysadmin 移除不可用的注册页与找回密码页（issue #24）

**报告**：[#24](https://github.com/NovaWorks/ZCard/issues/24) 指出正式后台存在两个**未接入
API 的装饰性页面**：

1. `/admin/#/auth/register` 静态路由可达注册页，提交表单后 `setTimeout` 模拟 1 秒延迟即提示
   「注册成功」并跳回登录——**无任何 API 请求、不创建用户**，纯属虚假反馈；
2. 登录页「忘记密码」链接指向 `/admin/#/auth/forget-password`，该页提交函数为空实现
   `const register = async () => {}`，点击无任何反应。

后端虽有 `/api/auth/register` / `/api/auth/send-reset-code` / `/api/auth/reset-password`，但均面向
**前台顾客**（register 创建的是 `user` 角色账号，受 `register_open` 开关控制），不应被后台接入。

**核实**：属实。`sysadmin/src/views/auth/register/index.vue` 的 `register()` 留有
`TODO: 替换为真实 API 调用` 注释，成功提示由 `setTimeout` 伪造；
`forget-password/index.vue` 的提交函数为空。两页均由 `staticRoutes.ts` 注册、无需登录即可访问。

**决策**：后台定位是管理面板，**管理员账号不开放自助注册，也不提供线上找回密码**（管理员账号
由超级管理员在后台「系统管理 → 用户管理」创建/重置密码；前台顾客的注册与找回密码在 storefront
`/register`、`/forget-password` 完成）。因此直接移除这两个页面，而非接入前台 API。

**修复内容**（均为 sysadmin 前端，后端零改动）：

- `sysadmin/src/router/routes/staticRoutes.ts`：删除 `Register`、`ForgetPassword` 两条静态路由，
  附注释说明定位与替代路径；未登录访问 `/auth/register`、`/auth/forget-password` 现按守卫逻辑
  重定向到登录页；
- 删除 `sysadmin/src/views/auth/register/`、`sysadmin/src/views/auth/forget-password/` 两个视图；
- `sysadmin/src/views/auth/login/index.vue`：移除「忘记密码」链接（保留记住密码）；
- `sysadmin/src/locales/langs/{zh,en}.json`：清理 `register.*`、`forgetPassword.*`、
  `menus.register`、`menus.forgetPassword`、`login.forgetPwd`、`login.register`、
  `login.noAccount` 等死键（`zcard.setting.*` 属前台设置页文案，保留）；
- 重建 `public/admin` 编译产物（项目约定产物入库）。

**验证**：改动文件 ESLint 通过（全量 lint 的 3304 个告警为存量问题，与本次无关）；`pnpm build`
成功；产物中已无 `auth/register`、`auth/forget-password` 路由字符串与「注册成功」假成功文案。

**影响范围**：仅 sysadmin 前端与编译产物；后端 API、数据库、storefront 均未改动。前台顾客的
注册/找回密码流程不受影响。

## 升级与使用

- 通过后台「在线更新」或 `git pull` 升级；**无数据库变更、无依赖变更**；
- 管理员忘记密码：由超级管理员在后台重置；若为超管本人丢失密码，在服务器执行
  `php artisan zcard:reset-admin-password`（支持 `--username=` / `--password=`，不传则随机生成）。
