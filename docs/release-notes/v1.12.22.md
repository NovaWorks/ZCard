# v1.12.22

## 🐛 修复:前台「我的订单」查不到已购订单(订单查询正常)

### 现象

登录用户在 storefront 购买卡密后,打开「我的订单」列表为空;但用「订单查询」
(订单号 / 联系方式)能查到该订单。

### 根因

「我的订单」按 `user_id` 过滤,「订单查询」按 `order_no` / `contact` 过滤 ——
两者结果差异说明**订单的 `user_id` 恒为空**。

- `POST /api/orders`(下单)与 `POST /api/orders/batch`(购物车批量下单)路由**不在**
  `auth:sanctum` 中间件组内。
- 控制器用 `$request->user()?->id` 取当前登录用户,而 `$request->user()` 默认走
  `web` guard(session driver),**无法解析 storefront 发送的 Bearer token** → 恒为 `null`。
- 结果:登录用户下单时 `user_id` 写入 `null`,订单创建与支付均正常,
  但「我的订单」按 `user_id` 查询永远为空;「订单查询」不依赖 `user_id`,故正常。

`PaymentController` 此前已踩过同一坑并修复(显式 `$request->user('sanctum')`,
见其 55–57 行注释),本次对 `OrderController` 补齐。

### 修复

`app/Http/Controllers/Api/OrderController.php`:
- `create()`:游客下单判断与 `user_id` 传递改为 `$request->user('sanctum')`。
- `batch()`:同上。

游客(无 token)下单行为不变,`user_id` 仍为 `null`。

  购物车批量下单同样归属登录用户。
