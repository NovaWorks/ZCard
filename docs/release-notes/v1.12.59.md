# v1.12.59

## 易支付配置简化

- 按 acg-faka 的易支付接入方式重新整理标准配置，新配置只需填写支付网关、商户 ID、商户密钥和需要启用的支付方式。
- 支付网关支持直接粘贴站点根地址或带 `/submit.php`、`/mapi.php` 的地址，保存时会自动归一，避免重复拼接导致下单地址错误。
- 后台启用通道前会校验网关地址、商户凭据和支付方式，缺少必要配置时直接提示，不再让无效配置进入线上支付流程。
- 前台将易支付中启用的支付宝、微信支付等方式分别展示，下单时明确提交用户选择的 `type`，不再依赖不同易支付程序行为不一致的聚合收银台。
- 保留历史 RSA/RSA2 配置与多种 PEM、Base64、转义换行密钥格式兼容；已有 RSA 通道可继续使用，新配置默认采用标准 MD5 协议。

## 回调地址与域名修复

- 易支付后台展示地址和实际提交的异步通知地址统一为 `/api/payments/callback/epay`，旧的 `/api/payments/notify/epay` 地址仍然可用。
- 新增独立的“支付回调域名”系统设置，部署在反向代理、容器或内网端口后时可明确填写公网 HTTPS 域名。
- 未单独填写回调域名时，系统优先使用当前公网访问域名；当前请求是 `localhost`、私网 IP 或代理协议不正确时，自动使用店铺域名进行修正。
- 后台配置页面会直接显示最终生效的完整回调地址，并提示易支付无需再手工配置站内固定地址。

## 易支付签名与通知兼容

- 易支付下单参数和 MD5 签名规则与 acg-faka 保持一致，补齐 `type` 与 `sitename` 参数。
- 回调同时兼容 GET、表单 POST 和 JSON 请求，并支持 `TRADE_SUCCESS`、`TRADE_FINISHED` 两种成功状态。
- 回调验签算法只使用后台保存的通道配置，通知参数不能临时切换或降级验签算法。
- 兼容部分易支付程序不返回商户 ID 的通知；返回商户 ID 时仍会严格核对，防止其他商户的合法通知串入当前通道。
- 回调金额只接受合法的两位小数金额，并使用高精度整数换算为分，避免浮点精度影响金额核对。

## 支付状态一致性

- 同一订单的并发通知通过数据库行锁串行处理，已经成功的订单直接返回成功，避免重复发货。
- 支付流水更新、订单支付状态和同步发货纳入同一事务；任一步骤失败时整体回滚，由支付平台继续重试。
- 聚合支付会在全部关联订单完成入账后再更新支付流水，避免出现流水已成功但部分订单仍未支付的中间状态。

## 管理端与前台

- sysadmin 易支付配置页隐藏标准接入不需要的历史高级字段，仅在已有 RSA/RSA2 通道中显示兼容配置和迁移提示。
- 系统设置页新增支付回调域名输入项，并对协议、路径、查询参数进行服务端校验。
- 单品支付、购物车结算和余额充值页面均支持按易支付具体支付方式发起请求。
- 重新构建并提交 sysadmin 与 storefront 生产资源，服务器在线更新后无需安装 Node.js。

## 回归验证

- 新增标准易支付签名、网关地址归一、支付方式传递、JSON 回调、服务端验签算法锁定和配置字段测试。
- 新增公网回调域名覆盖 localhost、店铺域名兜底的回调地址测试。
- 更新购物车聚合支付测试，覆盖易支付具体方式选择和最终跳转参数。
