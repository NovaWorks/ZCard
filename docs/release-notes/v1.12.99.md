# v1.12.99

## 🐛 修复：sysadmin 干净检出后无法安装、构建或启动 lint（issue #18）

**报告**：[#18](https://github.com/NovaWorks/ZCard/issues/18) 指出干净检出 `sysadmin` 后
四件事全部失败：`pnpm install` 的 `prepare` 在子目录执行 `husky` 找不到 `.git`；`pnpm build`
的 `vue-tsc` 先于自动导入声明生成而报数百个未定义符号；`pnpm lint` 因读取被 gitignore 的
`.auto-import.json` 直接 ENOENT；仓库钩子调用全局 `pnpm`，Corepack 环境无法提交。

**核实**：全部属实，且发现两个连带问题——

- `core.hooksPath` 在维护者本机也从未设置成功，即钩子系统此前从未生效过；
- husky v9 钩子执行时 cwd 是**仓库根**，而根 `package.json` 没有 `lint:lint-staged`
  脚本——即使钩子装上，原脚本也会失败。

**修复内容**（全部在 `sysadmin/`，后端与业务代码零改动）：

1. `package.json`：`prepare` 改为 `cd .. && husky sysadmin/.husky`（husky v9 支持目录
   参数，从仓库根安装钩子），干净检出 `pnpm install` 即正确设置 `core.hooksPath`；
2. `package.json`：新增 `packageManager: "pnpm@10.22.0"`，固定包管理器版本，Corepack
   环境可直接使用；
3. `.husky/pre-commit`：改为 `pnpm --dir sysadmin run lint:lint-staged`，适配钩子的
   仓库根工作目录；
4. `.husky/commit-msg`：改为 `pnpm --dir sysadmin exec commitlint`（本地安装，不再
   `pnpm dlx` 每次提交联网下载），并先把 `$1` 转为绝对路径（`--dir` 后相对路径失效）；
5. `src/types/import/auto-imports.d.ts`、`src/types/import/components.d.ts`、
   `.auto-import.json` 移出 `.gitignore` 纳入版本控制——三者为内容稳定的生成物，
   `vue-tsc` 与 `eslint.config.mjs` 在干净检出时就要读取。比报告建议的「调整构建顺序」
   更稳：类型检查仍在构建产物生成**之前**执行（fail-fast 语义保留）。

**验证**（干净克隆全流程实测）：

- `pnpm install --frozen-lockfile` 成功，克隆仓库的 `core.hooksPath` 被正确设置为
  `sysadmin/.husky/_`；
- `pnpm build`（`vue-tsc --noEmit && vite build`）在无任何缓存/生成物的状态下通过；
- `pnpm lint` 能加载配置正常执行（既有 3,306 个 Prettier 存量告警仍在，属独立基线
  问题，报告本身也注明独立处理，本次不动）；
- 提交实测：规范消息（`chore: ...`）通过 commitlint 并成功提交，lint-staged 只处理
  sysadmin 下的暂存文件（同批暂存的 storefront 文件不受影响）；非规范消息
  （`bad message no type`）被 commitlint 拒绝，提交被阻止。

**影响范围**：仅前端工程化配置与三个生成声明文件入库；业务代码、编译产物、后端、
storefront 均不受影响。生产部署不涉及（无需 Node.js）。

## 升级与使用

- 通过后台「在线更新」或 `git pull` 升级；无数据库变更；
- 开发者下次在 `sysadmin/` 执行 `pnpm install` 后钩子即生效（本机此前从未生效过），
  提交会触发 lint-staged 自动修复与 commitlint 校验；如需跳过可 `git commit --no-verify`。
