# v1.12.8

## 🐛 修复:下单验证码输入正确仍提示错误

### 根因
`config/captcha.php` 只定义了 `default`/`flat`/`mini` 场景,**缺少 `trade`(下单)场景**。
前端生成验证码时请求 `/api/captcha/trade` → `captcha_src('trade')` → 图片用 `create('trade')`
生成。由于 `trade` 场景未配置,mews 回退到**类默认值**(`length=5`、`encrypt=true`),
与 `default` 场景(`length=4`、`encrypt=false`)不一致,导致验证码生成/校验行为异常,
用户输入正确也可能被判定错误。

### 修复
- 新增 `trade` 场景配置,与 `default` 同参数(`length=4`、`encrypt=false`)。
- 同时 `bgImage=false` 去除背景纹理,验证码更清晰,降低用户误输概率。

## ✅ 验证
- 修复后 `create('trade')` 正常返回,session 中 `encrypt=false`。
- 单会话 curl 链路验证:图片生成 → 同 cookie 校验正确答案通过。
- 日志确认:图片请求与下单提交使用同一 session,captcha 数据存在、encrypt=false。
- 验证码图片从带干扰纹理变为纯白底黑字,OCR 可稳定识别(修复前多模式不一致)。
